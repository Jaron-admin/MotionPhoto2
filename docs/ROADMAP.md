# 动态照片转换：开发路线

依据 Notion《Codex 任务书：动态照片转换 开发路线》，2026-10-19 整理。
一次只推进一个阶段，验证后再发布和进入下一阶段。原则：先能用，再好用，最后考虑商业化。

## 项目约束

- 基于 Jaron-admin/MotionPhoto2，保留原作者 Petr Vyskocil（PetrVys）版权和 MIT LICENSE。
- 先读代码、用中文说明计划；小步提交，每步保持可运行，改后运行测试。
- 转换逻辑保持独立，不依赖 macOS 专属 API；界面只调用核心，路径兼容 Windows/Linux。
- 当前只推进 macOS 中文版，不新增其他平台产品。
- 每个阶段交付本地验证方法和发布方法。

## 阶段 0：摸底与测试基线（本次范围）

- 梳理目录、转换流程、依赖和 App 打包方式，见 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)。
- 使用自动生成的小型 JPG/HEIC + MOV/MP4 样本验证已有功能，见 [TESTING.md](TESTING.md)。
- 本地执行一条命令运行测试；缺少依赖必须失败，不能跳过整套集成测试。
- 两条已有打包工作流均依赖测试通过；中文版成品再运行相同转换测试。
- 建立本路线图；不修改功能代码。
- 已知缺陷单独登记在 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)，不把预期失败称为功能通过。

验收：本地测试无意外失败；当前提交的 GitHub Actions 绿色；发布前确认成品可打开。
本地验证与 GitHub 验证分别报告，不能用 YAML 检查代替远程运行结果。

## 阶段 1：反向转换

目标：Google/安卓动态照片转换为 iPhone 实况照片，导入 Mac「照片」或 iPhone 后可播放。

1. 先调研格式细节并确认方案，再写代码。
2. 识别 Google Motion Photo 的 MotionPhoto/MicroVideo 元数据及视频偏移，支持 JPG 与 HEIC。
3. 提取内嵌视频，生成图片 + MOV，写入相同的 Apple ContentIdentifier；研究并验证视频的实况元数据轨道，不能只凭同名文件认定成功。
4. 保留拍摄时间、GPS、设备等元数据；非动态照片跳过并说明原因。
5. 界面增加「实况 → 动态」/「动态 → 实况」方向切换。
6. 补充测试和 Mac「照片」导入验证说明。

验收：真实 Pixel 动态照片转换后拖入 Mac「照片」，显示「实况」并能播放。

## 阶段 2：批量与数据保全

1. 拖入整个目录，递归配对 HEIC/JPG 与 MOV（部分目录处理已有实现，需要补齐体验及边界验证）。
2. 输出到新目录，永不覆盖原文件。
3. 进度条、成功/跳过/失败统计、中文 CSV/TXT 结果报告。
4. 单文件失败不影响其他文件。
5. 保留拍摄时间和文件修改时间，方便相册排序。
6. 处理已记录的元数据保全问题，包括 XMP-1。

## 阶段 3：更多安卓品牌

按小米、三星（Motion Photo/SEF）、华为/荣耀、OPPO/vivo 的优先级调研。

1. 编写 `docs/formats.md`，记录识别依据和视频存储位置。
2. 统一「检测 → 提取 → 转换」接口，便于新增格式。
3. 不支持的格式提供清楚提示。
4. 每品牌至少一个用户提供的真实样本；未取得样本时不声明该品牌已支持。

## 阶段 4：体验与界面

1. 转换前显示缩略图和识别结果。
2. 设置输出位置、文件命名、画质。
3. 完成通知与访达定位。
4. 「关于」页显示正确版本、PetrVys 署名与 MIT 协议。
5. 中英双语 README、截图、常见启动问题说明。
6. 统一 App/Release 版本，修复 CLI 配置写入 App 包导致签名失效的 SIGN-1 问题。

## 阶段 5：公开推广

1. README 首屏说明问题、支持设备和下载地址。
2. Release 自动生成更新日志。
3. 可选 Homebrew cask。
4. 捐赠链接由用户提供后再填写。
5. 准备 V2EX、少数派、小红书介绍草稿；发布由用户决定。

## 暂不实施

- Apple 开发者签名、公证及相关付费服务。
- 付费批量版、Mac App Store、Immich 集成。
- 新增多平台版本。以后先做命令行矩阵验证，再评估浏览器本地处理或 Tauri/Flutter。

## 卡住时

先解释问题并给出两个方案。同一问题持续超过 30 分钟，停止盲目尝试，记录阻塞和下一步。签名或系统安全提示按具体错误诊断，不直接修改用户已安装的 App。
